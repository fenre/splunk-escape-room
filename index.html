01 The Concept

An inverse escape room where players break in instead of out. Use Splunk to complete 26 tasks across five acts — from the Christmas party to the vault heist.

Christmas Eve. Nakatomi Plaza, Los Angeles. A tower of glass and steel, and tonight there's a party on the thirtieth floor. You're not here for the party. You're part of the team that just took the building. Five acts. Twenty-six tasks. From party recon to the final extraction. There's a vault. Seven locks. $640 million in bearer bonds. The man who knew the codes is gone. So we crack it ourselves.
🔍

Splunk Is the Room

The "escape room" is a Splunk environment. Players investigate synthetic log data to discover codes, sequences, and procedures.

🏛

Physical Vault Model

A tangible Nakatomi Plaza model with 7 seal inputs. Codes from Splunk are entered on the physical vault to open each seal.

🎬

Die Hard Theme

Christmas Eve, 1988. Players are Hans Gruber's tech crew. Easter eggs, quotes, and characters from the film are woven throughout.

⚡

The Seventh Seal

Six seals open with codes. The seventh is a meta solution — a physical trick outside the system, just like in the movie.

SPL Queries

Most tasks are solved with SPL: stats dc(), sort, lookup, rex, transaction, time ranges, and cross-references between indexes and lookups. Answers are numeric codes or alphanumeric text entered on the vault keypad.

Ciphers, Cross-Refs & Multi-Step

Tasks may require ROT13 decoding, cross-referencing multiple lookups, multi-step composite puzzles (solve two sub-objectives in sequence), or even a meta power-cut solution from the movie.

Progressive Hints & Nudges

Each task has up to four hint levels. A dynamic nudge system glows the hint button if you're stuck too long. Using hints reduces your score; the 4th hint reveals the answer at 0 points.

Scoring, Traps & Dossier

Points awarded per task based on speed and hint usage. Trap codes trigger extra penalties. Completing a task reveals a character-attributed story beat and adds intel to your dossier.

v2.16.0 26 Apr 2026 Scenario Packs + i18n (Phase 5f / Q3 / Q4)
ScenarioPacks IIFE
  • ?scenario=<name> URL flag; allow-list default | roof | afterparty. Anything else silently falls back to default with no fetch attempt
  • Three packs in scenarios/: default (canonical Christmas-noir, no-op overlay), roof (rooftop edition, helicopter wind ambient, Karl/Theo rooftop chatter), afterparty (forensic debrief, McClane reconstructing the heist from morning-after logs)
  • Schema v2: $schema_version: 2 + $id + optional metadata / ambient / story_beats / intercepts / endings. Story-beat keys match /^[a-zA-Z0-9_]{1,40}$/; ending keys match /^[a-zA-Z_]{1,32}$/. Unknown keys silently dropped at validation
  • Inline <script id="nakatomi-scenario" type="application/json"> block for booth-friendly deploys (zero extra round-trips, file://-safe, kiosk-CSP friendly)
I18n IIFE + locale packs
  • ?lang=<code> URL flag; allow-list en | es | de | ja. Two packs ship: i18n/en.json (canonical) and i18n/es.json (Spanish proof-of-concept)
  • DEFAULTS table covers ~30 most-visible UI strings (mode-select, HUD, pause, victory, game-over). Bulk inline strings stay inline until the v3.0 capstone refactor
  • I18n.t(key, fallback) resolution chain: inline-loaded translations → DEFAULTS → fallback arg → key itself. Key validated against /^[a-zA-Z0-9_.]{1,80}$/ so a future caller passing user input can't traverse outside the allow-list
  • Regression suite enforces full coverage: every locale pack must contain every DEFAULTS key (catches a partial translation shipping by accident)
Security model (both modules)
  • Allow-list bounds — pack $id and lang code MUST match the in-code allow-list. Fetch URL fixed-shape (scenarios/<allowlisted>.json / i18n/<allowlisted>.json) — no path traversal, no scheme override
  • Size caps — body rejected if > 64 KB (scenario) / 32 KB (i18n). Each string capped at 2048 / 1024 bytes. content-length checked pre-text() read
  • Prototype-pollution defense — keys named __proto__, constructor, prototype silently dropped during validation
  • No DOM injection — every override rendered through escHTML() at the consuming call site. Pack content treated as untrusted input even from the project's own packs
  • file:// fallback — runtime detects location.protocol === 'file:' and skips fetch entirely; use the inline <script> block when shipping offline

v2.14.0 26 Apr 2026 Adaptive Audio + Ode to Joy + Mix Panel (Phase 5h)
Adaptive 3-layer audio engine
  • Bus topology: _audioMasterBus → destination, with _audioAmbientBus / _audioMusicBus / _audioSfxBus feeding into master. tone() and noise() accept an optional bus arg routing to the named GainNode (default 'sfx' so 30+ existing cue functions still work)
  • AudioMix.crossfade(layer, target, durMs) animates the named layer's gain via linearRampToValueAtTime — replaces v2.13's hard on/off behaviour with smooth tonal shifts
  • Bus references named with _audio*Bus to avoid colliding with the legacy ambientGain per-oscillator gain in startAmbient()
Beethoven's Ode to Joy on vault-open
  • Public-domain melody from Beethoven's 9th, 4th movement (Schiller's An die Freude) — first 8 bars: E E F G G F E D C C D E E D D. Synthesised in code, no recording-licensing surface, single-file distribution intact
  • Plays through the music bus with a sustained C3+G3 fifth underneath for the orchestra-entrance feel + an octave-up sparkle on the long final note
  • Fires only on the DEFAULT ending. The analyst / cowboy / speedrunner branches keep their bespoke per-ending stings; layering Ode on top would muddy them. The default ending is the canonical “Welcome to the party, pal.” resolution — iconic Die Hard moment, where the Beethoven motif lands hardest
Per-act motifs + audio mix panel
  • AudioMix.playActComplete(actIdx) — 5-note arpeggios unique per act so players unconsciously learn each act's signature. Act 1 C major / Act 2 C minor / Act 3 A minor → B half-dim / Act 4 G dim → climbing / Act 5 C major → D resolution
  • In-pause Audio Mix panel (toggled by “AUDIO MIX & CAPTIONS” button with aria-expanded): four sliders (Master / Music / SFX / Ambient, 0–100 with visible “75%” readouts) and three checkboxes (Mono / single-ear, Reduced audio intensity, Audio captions)
  • Persistent settings under localStorage['nakatomi_audio_settings']. Every tweak emits an audio_setting_changed telemetry event so the booth dashboard can answer “did anyone find the controls?”
